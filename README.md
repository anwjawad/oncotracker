# منسّق الأورام — النسخة الثانية

إعادة بناء كاملة لتطبيق [oncotracker](https://github.com/anwjawad/oncotracker). تبقى البيانات في نفس ملف Google Sheets، لكن البنية تغيّرت حتى يصير **لكل مريض ملف واحد** تتفرّع منه زيارات العيادة وحالات اللجنة والمتابعات.

## ما الذي تغيّر

| قبل | الآن |
|---|---|
| المريض يتكرر كسطر نصي في كل ورقة، والاسم يُقصّ لكلمتين عند الاستيراد | ملف مريض واحد برقم الملف. الاسم الكامل يُحفظ، ويُكمَّل الاسم المختصر من ملفات الاستيراد |
| الاستيراد يضيف كل الصفوف مباشرة | شاشة مراجعة: ربط الأعمدة يدوياً، ومطابقة كل صف مع المرضى الموجودين، وتخطّي المكرر، وإيقاف الصفوف التي فيها نفس رقم الملف باسم مختلف |
| لا يوجد مكان لتصحيح الأخطاء | صفحة **تصحيح البيانات**: أرقام ملفات مكررة، ودمج الملفات، وأرقام هواتف فقدت الصفر الأول، وأرقام عربية، وأسماء مختصرة، وبيانات ناقصة، ولصق أرقام الهواتف دفعة واحدة |
| لجنة الحالات = جدول | **جلسات** مرتبة بالتاريخ، وفي كل جلسة جدول أعمال تتقدّم فيه كل حالة: مُدرجة ← جاهزة ← عُرضت (والقرار مسجّل) أو مؤجّلة لجلسة لاحقة. بعد تسجيل القرار يُقفل، وأي إضافة لاحقة تكون ملحقاً مؤرّخاً |
| المتابعة نص داخل السطر، وإنهاؤها يلصق HTML في خطة العلاج | كل متابعة مهمة مستقلة لها نوع وتاريخ استحقاق وسجل محاولات اتصال. تُجمَّع حسب: متأخرة / اليوم / هذا الأسبوع. لا تُغلق إلا بكتابة ما تمّ |
| قرار اللجنة لا يولّد شيئاً | تسجيل القرار يُنشئ متابعاته مباشرة (تبليغ، تحويل، حجز موعد، فحوصات، تصريح) |
| «بانتظار التبليغ» و«بانتظار موعد» قوائم منفصلة | مهام **تلقائية** في نفس لوحة المتابعات، تختفي وحدها عند التبليغ أو تحديد الموعد |
| لا يُعرف من عدّل ماذا | سجل تعديلات لكل مريض: مَن، ومتى، والقيمة قبل وبعد |
| فشل الحفظ = رسالة `alert` وضياع التعديل | كل تعديل يُحفظ على الجهاز أولاً، ثم يُرسل للخادم ويُعاد إرساله تلقائياً عند انقطاع الاتصال. حالة الحفظ ظاهرة دائماً أعلى الصفحة |

## التشغيل

التطبيق منشور على GitHub Pages: **https://anwjawad.github.io/oncotracker/**. أي تعديل يُدمج في فرع `main` يظهر هناك خلال دقيقة أو دقيقتين.

للتشغيل على الجهاز: افتح الملف `تشغيل التطبيق.bat` (يحتاج Python).

النسخة القديمة محفوظة كما هي في مجلد [`backup/`](backup/)، وتفتح على https://anwjawad.github.io/oncotracker/backup/ ما دام خادم Apps Script القديم منشوراً.

| المجلد / الملف | المحتوى |
|---|---|
| `index.html`، `css/`، `js/` | التطبيق (الواجهة) |
| `js/views/` | صفحة لكل قسم: اليوم، اللجنة، العيادة، المتابعات، المرضى، تصحيح البيانات، التقارير، الإعدادات |
| `backend/Code.gs` | خادم Google Apps Script |
| `backup/` | النسخة القديمة كاملة |

التطبيق متصل مباشرة بخادم Apps Script الخاص بالقسم. للتجربة ببيانات وهمية دون المساس بالبيانات الحقيقية: الإعدادات ← فعّل «وضع تجريبي» ← حفظ ← «تعبئة بيانات تجريبية».

## الربط بملف Google Sheets ونقل البيانات القديمة

1. افتح ملف Google Sheets الحالي ← **Extensions ← Apps Script**.
2. **انسخ ملف Code.gs القديم احتياطاً**، ثم استبدل محتواه بالملف `backend/Code.gs` واحفظ.
3. اختر الدالة `setup` واضغط **Run**، ووافق على الصلاحيات.
4. **Deploy ← Manage deployments ← (القلم) Edit ← Version: New version ← Deploy**. هكذا يبقى نفس الرابط، وهو **مدمج في التطبيق** (`js/settings.js`)، فلا يحتاج أحد أن يكتبه. لا تستخدم *New deployment* لأنه يعطي رابطاً جديداً.
5. في التطبيق: **الإعدادات** ← **ترحيل بيانات النسخة القديمة**.

الترحيل يقرأ `PostClinicBookings` و`NewCasesMeeting` وينشئ منهما الأوراق الجديدة `Patients` و`ClinicVisits` و`CommitteeCases` و`FollowUps` و`Activity`. **الأوراق القديمة لا تُعدَّل ولا تُحذف**، ويمكن تشغيل الترحيل أكثر من مرة دون تكرار. بعده افتح «تصحيح البيانات» لمراجعة المكرر والناقص.

> بعد نشر النسخة الجديدة سيتوقف التطبيق القديم عن الكتابة، لأن الخادم الجديد لا يفهم أوامره القديمة. انقل الفريق كله للنسخة الجديدة في نفس اليوم.

## ملاحظات

- كل منسّق يكتب اسمه في الإعدادات على جهازه، فيظهر في سجل التعديلات.
- أعمدة الأوراق الجديدة بصيغة نص، حتى لا يحذف Sheets الصفر الأول من الهواتف وأرقام الملفات.
- صور ملاحظات الأخصائي تُرفع إلى مجلد `Onco Tracker Attachments` في Drive، ويستطيع مشاهدتها **أي شخص معه الرابط** (كما في النسخة السابقة) حتى تظهر داخل التطبيق.
